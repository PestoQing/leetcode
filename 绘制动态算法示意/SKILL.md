# 绘制动态算法示意

把一份算法解法（通常是 `xxx.py`）做成**离线单文件** `xxx.html`：左侧是逐步动画，右侧是 VS Code 风格的源码并高亮当前执行行。
引擎（播放器、布局、代码高亮、平滑过渡、自检）已经写好，放在 `assets/template.html` 里；每道题只需要重写其中的 **DEMO** 部分。

## 用户的固定偏好（必须遵守）

1. **明亮主题**：浅色背景 `#f5f7fb`，白色卡片，蓝 / 绿 / 红 / 琥珀 / 紫作为语义色。
2. **代码区用深色背景**，配色照搬 VS Code Dark Modern + Pylance 的 Python 语义高亮（引擎已经实现，包括括号配对着色和缩进参考线）。代码要嵌入 .py 的**完整原文**，不能改写或删减。
3. **生成的 html 和对应的 .py 放在同一目录**，文件名相同：`文远1.py` → `文远1.html`。
4. **步与步之间要平滑过渡**：DOM 尽量复用并只改 class/文字（CSS transition），列表用 `AV.keyed`（FLIP 重排），图形位置用 `AV.animate` 补间。不要每一步都用 innerHTML 整块重绘。
5. **任何文字都不能被遮挡**：选中态不能用 `transform` 位移或放大去压到相邻文字（比如时间轴的 index）。选中效果只用颜色、边框和 `box-shadow` 光环，并且在布局上为光环留出间距；有光环的元素加 `data-solid data-ring="3"`，自检时会用到。SVG 标签加白色描边做底，并做避让。
6. **代码区要足够宽，且不能出现横向滚动条**：长行自动换行并保持悬挂缩进；分隔条可以拖动调整宽度（双击恢复默认），可以整体折叠，可以隐藏纯注释行，字号可调。
7. **浏览器在 80% 缩放时（以及 100%），左侧动画必须一屏放下，不能上下滚动**：整页高度为 100vh，各区域尺寸固定；内容多时在卡片内部滚动，或者缩小格子尺寸，不要把页面拉长。
8. **布局固定**，每道题都用同一套框架：
   - 顶部：标题 + 一句话思路
   - 左列从上到下：工具栏（输入、预设、播放控制、进度条）→ 统计卡片行 → 主画布卡片 → 底部两列（左：当前步骤说明 + 状态卡片；右：辅助数据结构卡片）
   - 右列：代码位置
9. **统计卡片沿用现在的风格**：粗体标题，下面是 32px 加粗彩色数字，可带灰色小单位或副标题；数值变化时数字滚动并闪一下光环。像「累计加载次数 res」这样的关键量一定要放进去。
10. **表示指向关系的弧线 / 连线必须带箭头**：使用 SVG marker，箭头颜色和线一致。CSS 选择器不要误伤 `<defs>` 里 marker 的填充（`fill:none` 只设给 `svg > g path`）。自检会报「连线缺少箭头」。
11. **进度条可以点击，也可以拖动**：带圆形拖柄和「第 N 步」提示气泡。拖动时每个显示帧只渲染最新指向步骤，中间快照允许跳过；松手必须落在最终位置。另外支持 Home / End 键。正常播放仍逐步展示平滑动画。
12. **用户每提一次意见，马上重新生成上一个 html**：同时修改本 skill 的 `assets/template.html` 或本文件，让以后生成的页面也带上这条意见；然后重新跑自检并截图确认。

13. **播放速度默认选择最快一档，越快填充越满**：滑块采用从左到右递增的速度值（`min="0" max="100" value="100"`），左侧慢、右侧快；最快时滑块在最右端，轨道完全填满。不要使用 `direction:rtl` 翻转控件。用 `2600 - 23 * value` 将速度换算成每步等待毫秒数（最慢 2600ms，最快 300ms），播放计时与动画时长均使用换算后的值。模板和已生成页面保持一致，用户仍可手动调慢。

14. **数学公式按论文（MathType）格式排版**：不要用 `q1q2²e^{q2c}∇c∇cᵀ` 这种纯文本拼写。页面文字（desc、formula、subtitle、统计/输入标签、hint）里的公式一律写成 TeX，并用 `$…$`（行内）或 `$$…$$`（独立一行）包起来，例如 `$q_1 q_2^2 e^{q_2 c}\\, \\nabla c\\, \\nabla c^{\\top}$`。引擎会离线转成 MathML，用 Cambria Math 等数学字体排版：变量斜体，上下标、分式、根号、重音符都是真正的数学排版。
   - 写在 JS 字符串里时反斜杠要写两次（`'\\frac'`）。模板字符串里 `$` 后紧跟 `${…}` 插值没问题，例如 `` `$\\alpha = ${a}$` ``。
   - 支持 `^ _ {} \frac \sqrt \hat \bar \tilde \vec \mathbf \boldsymbol \mathrm \text \operatorname \mathcal \mathbb \left \right`、希腊字母、`\max \min \exp \log \operatorname{softmax}` 等函数名、`\le \ge \to \leftarrow \sim \in \nabla \top \sum \prod \cdot \times \lfloor \lceil \lvert \mid \quad \, \;`。公式里要上色时用 `\class{g}{\alpha}`，会套用 `.formula .g` 之类的样式，不要在 `$…$` 中间插 `<span>`。
   - 多字母变量写成下标或 `\text{}`：`Q_{uu}`、`J_{\text{new}}`、`\tau_{\text{ref}}`。
   - 带公式的节点用 `AV.setHTML(node, html)` 或 `AV.setText` 写入，它们按原始字符串判断是否变化。**不要**再写 `if (node.innerHTML !== html) node.innerHTML = html`：排版后 innerHTML 已经不等于源串，这样每一步都会误判重绘、触发闪烁。直接写 innerHTML 的内容也会由引擎的 MutationObserver 自动排版。
   - 逐步代入 Python 变量的计算过程（如 `dp[i] = dp[p] − 1 − size[j] × P(j 先)`）属于代码追踪，保持与源码一致的等宽写法；真正的数学式（论文公式、期望、求和、取整、复杂度 `$O(n^2)$`）用 TeX。代码区和 SVG 里的文字不做公式排版。
   - 旧页面升级：`python <skill>/scripts/patch_tex.py <页面.html>...`。它会注入或更新引擎里的公式排版代码，并改写 DEMO 中的 innerHTML 比较写法（可重复执行）。排版器源码在 `scripts/tex_engine.js`，修改后重新执行 patch 同步到模板和各页面。

## 工作流程

1. **读懂解法**：完整阅读目标 `.py`，理清阶段划分、关键变量和值得可视化的数据结构。
2. **复制模板**：`cp <skill>/assets/template.html <py 所在目录>/<同名>.html`
3. **嵌入源码**：`python <skill>/scripts/embed_source.py <同名>.html <同名>.py`
4. **重写 DEMO 部分**：即最后一个 `<script>`，以及 `<style>` 里 `DEMO STYLE` 以下的样式。建议把它们写成临时目录里的 `demo.css`、`demo.js`，再用 `python <skill>/scripts/splice_demo.py <同名>.html demo.css demo.js` 填进去（可反复执行）。ENGINE 部分不要改；如果确实需要改，说明这是通用问题，要同步改回模板。DEMO 对象需要实现：
   - `file`、`title`、`subtitle`
   - `inputs`：`[{id, label, value, type?, width?, flex?}]`
   - `presets`：`[{label, values:{id: value}}]`，要包含题目里给出的测试用例
   - `stats`：`[{key, label, color}]`，color 取 `red|green|blue|amber|purple|gray`
   - `panels`：`{canvas:{title,hint}, state:{title,hint}, aux:[{id,title,hint,grow?}]}`
   - `parse(values)`：返回 `{error}`，或者返回数据对象（并限制规模，保证一屏放得下）
   - `build(data)`：返回 steps 数组。每一步是一个**完整快照**，包含 `phase, tag:{text,kind}, desc(html), lines:[行号], stats:{key: 数字 | {v, unit, sub}}` 以及本题需要的状态字段。行号一律用 `AV.lineOf('源码片段', 第几处)` 来取，不要手写数字。
   - `mount(data, P)`：在 `P.canvas`、`P.state`、`P.aux[id]` 里一次性创建持久的 DOM。卡片外框在 `P.auxCard[id]`、`P.stateCard`。
   - `layout(data, P)`：按容器宽度计算格子尺寸。容器尺寸变化时引擎会自动调用。
   - `render(step, prevStep, data, P)`：根据快照更新 DOM。必须是幂等的，因为前进、后退、跳转都会调用它。
   - 引擎提供的工具：`AV.keyed`、`AV.animate`、`AV.setText(node, text, 'av-flash')`、`AV.setHTML(node, html)`（按原始串比较，含公式时必须用它）、`AV.tex(src, display)`（TeX → MathML 字符串）、`AV.typeset(node)`、`AV.flash`、`AV.el`、`AV.esc`、`AV.clamp`、`AV.dur()`、`AV.isInstant()`
5. **验证逻辑**：用 node 提取 `build` 跑题目里的测试用例，最终答案要和 `python xxx.py` 的输出一致。
6. **自检布局**：`python <skill>/scripts/check.py <同名>.html [步骤号 | 预设号@步骤号 ...]`。它会用无头 Edge 在 80% 和 100% 两种缩放下遍历**所有预设输入的所有步骤**，检查文字重叠、元素遮挡文字、左侧是否需要滚动、代码是否横向滚动，并截图到系统临时目录下的 `algoviz-shots/`（Windows 为 `%TEMP%`，Linux 为 `/tmp`；Linux 下自动使用 google-chrome / chromium）。必须两种缩放都是 OK；再用 Read 打开截图，人工看一眼效果。
7. 用 `start "" <同名>.html`（Linux 用 `xdg-open`）在浏览器里打开，然后向用户简要说明：页面怎么操作、演示了哪些内容、验证结果如何。

修改播放器交互时，另运行 `node <skill>/scripts/check_drag.cjs <同名>.html`，验证高频拖动合帧、松手落点、取消/丢失捕获清理、拖动中切换预设、分隔条宽度保存和恢复播放。该检查验证行为，不以无头浏览器帧率代表真实桌面性能。

## 设计要点

- 拖动进度条和代码分隔条沿用引擎的 `frameDrag`：事件只记录最新坐标，每帧至多更新一次，结束或被其他操作打断时清掉待执行帧并提交最新值。按下时缓存稳定的边界尺寸，不在每次移动时读布局。
- 拖动期间保持 `AV.isInstant()` 为真，DEMO 的补间用 `AV.animate` / `AV.dur()`，不要自建忽略瞬时模式的动画循环。拖动不启动数字补间、FLIP、闪烁或代码平滑滚动；松手后恢复正常播放动画。不要用逐次 `withInstant` 包裹移动回调，它会反复切换全局 CSS 并强制布局。
- `render` 复用节点，值未变时避免写 DOM；代码高亮仅更新变动行。几何计算放在 `layout`，尺寸未变时不在每一步重新计算。维护本题模块时不要引入每次鼠标移动遍历所有历史步骤的操作。
- 树算法涉及 `children` 时，在数组表中展示每个节点的直接子节点列表，逐步演示列表构建，并在判断独生子或寻找兄弟时高亮对应父节点行。期望收益等复合公式应拆分为含义、概率变化、数值代入与合计步骤。
- 数组读入与初始化按源码循环逐次展示：尚未赋值的位置显示 `·`，每次 append 或更新单独高亮，不提前展示最终数组；父节点字段使用 `parent` 或 `parent[i]`，避免只写含义不明的 `p`。
- 一个步骤只讲一件事。像"判断 → 执行"这样的过程拆成两步，desc 里说明**为什么**这样做，而不只是做了什么。
- 高亮的代码行必须和这一步的动作严格对应。
- 遇到含多个 `and` / `or` 的冗长逻辑判断，先在 Python 条件上方逐项添加中文注释，说明每个条件的含义、组合后的执行目的以及相关短路行为，保持原逻辑不变；随后将更新后的完整源码同步嵌入 HTML，并核对高亮定位。
- 集合与字典 DP 的当前计算面板显式展示 `new_visited`、`state`、`new_cost`，变量名与源码一致；显示集合加入新点、字典键和候选耗时的代入过程，无候选转移时清空对应值。
- 主画布优先使用"数组 / 时间轴格子 + SVG 弧线（指向关系）+ 滑动游标"这套表现手法（参考模板里的文远1示例）；树、图、栈等结构也用同样的持久 DOM / SVG + 补间方式实现。
- 颜色语义要一致：蓝 = 当前，绿 = 命中 / 成功，红 = 淘汰 / 失败 / 未命中，紫 = 预处理 / 辅助指针，灰 = 已处理或过期。
- 表格表头不要用 `position: sticky` 叠在滚动内容上，应把表头放在滚动容器外面（否则自检会误报遮挡）。
- 图结构（如 文远2 的道路图）：节点按圆周布局，边权标签与箭头标签做避让；有向箭头用二次曲线并向行进方向左侧弯，这样 a→b 和 b→a 不会重叠。
- 树结构（如 文远3 的二叉树）：叶子按顺序占等宽槽位，内部节点取子节点中点，层距按最大深度自适应；节点圆内写权值、左上角写 #编号，只在当前涉及的边上标概率等标签，其余数值放进表格，避免挤在树上。
- 取 SVG 里的连线元素时用 `svg > g path`，不要用 `svg path`：后者会先选中 `<defs>` 里 marker 的箭头头部，连线画不出来，箭头头部反而被改坏。
- 值域 / 前缀和类题（如 滴滴加减2）：每列是一个数值，从上到下依次是游标、下标、原始个数，再是几行前缀数组；还没扩容到的列用透明度隐藏而不删掉，这样列宽不会跳动。
- 统计卡片的数字补间会对数值取整（`Math.round`），带小数的量（ᾱ、cost、概率等）要先 `toFixed` 成字符串再传入；要和 Python 的 `:.4f` 显示一致时，注意 JS `toFixed` 与 Python 在 0.03125 这类"恰好一半"的值上舍入不同。
- 有补间的 SVG 元素，`layout` 里要清空补间起点（如 `U.last = null`），否则窗口尺寸变化后会从旧坐标飞过来。
- 自检只看文字元素自身的 opacity；要隐藏 SVG 标签，把 opacity 设在 `<text>` 上，而不是父 `<g>` 上。
- 论文类算法（如 自动驾驶/ 下的 DiffusionDrive、ResAD、CILQR）：py 用纯标准库 + 文件顶部常量、不读 stdin；需要随机数时 py 与 JS 各写一份相同的 mulberry32 + Box-Muller，保证数值逐位一致；网络用"闭式理想替身"（如 GMM 后验均值）代替，并在注释里写明是简化。
- 三维 DP 演示（如 Floyd）必须同时展示上一层的来源矩阵和当前层的结果矩阵，并分别高亮读取与写入的格子；历史切片下拉框不能替代并排对照。需要空间总览时配可旋转的三维分层网格，阶段维度与源码索引保持一致。
- 集合与字典 DP 的状态表按当前最优记录的实际纳入顺序展示节点（如 `{2, 1}`），不要为显示而按编号排序；状态去重仍按无序集合与停留点进行。显示顺序与内部规范化键分开，表头注明顺序含义。
- 页面支持 `#preset=P&step=N` 直接打开某个预设的某一步，方便截图排查。
- 有"尝试 → 失败 → 回退"分支的算法（如线搜索、拒绝步、回溯）：**默认预设**就要让失败分支出现至少一次（如 CILQR 默认预设第 1 轮 α=1 的候选代价未下降、α 减半后才接受）。用 node 跑 `build` 遍历参数，挑出步数适中、且包含失败分支的输入。
- 最后一步给出最终答案；有意义的话，再和朴素解法或其他策略做对比。
