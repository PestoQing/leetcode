## 一、代码风格

### 1. 实现选择

优先选择逻辑简单、容易理解和维护的实现。在满足题目限制的前提下，可以适当牺牲时间或空间效率。不为了优雅、压缩行数或最优复杂度引入不必要的技巧。题目明确要求特定复杂度时必须满足。

代码要像面试现场能够自然写出的实现。允许朴素写法和适度冗余，但不能故意制造错误、遗漏必要条件。正确性和题目要求优先于风格。

### 2. 变量命名

| 用途 | 优先命名 |
|---|---|
| 输入数组 | nums、nums1、nums2 |
| 结果 | res、ans |
| 临时变量 | tmp |
| 计数 | cnt、count |
| 下标 | i、j、index |
| 当前节点 | cur |
| 二分 | left、right、mid |
| 双指针 | head、tail 或 slow、fast |
| 滑动窗口 | left、right、current、max_len |
| 访问记录 | seen、last_seen |
| 图和树 | graph、children、parent、queue |
| 动态规划 | dp |
| 回溯 | back、path、start |

避免冗长英文命名和难懂缩写；必要时允许直观拼音。命名服务于含义，不强行把题目既有的变量全部重命名。

### 3. 列表与字典

列表优先从空列表或少量初始状态开始，通过 `append()` 构建。二维列表优先逐行建立 `row`，逐项 `row.append(...)`，最后 `dp.append(row)`。

避免为了让数值直接充当下标，预分配覆盖整个数值范围的 MAX 大数组。数值范围较大或稀疏时，优先字典、集合或排序。按实际问题规模构建数组允许。动态 append 扩展到最大数值仍占用相应空间，不能因此忽略内存限制。

不使用 `dict.get(key, default)`，新写算法代码统一用显式成员判断：

```python
cnt = {}
for num in nums:
    if num in cnt:
        cnt[num] += 1
    else:
        cnt[num] = 1
```

### 4. 语法和库

优先普通 `for`、`while` 和 `if/elif/else`。遍历下标可以使用 `for i in range(len(nums))`。允许简单列表推导式；正常使用 `len`、`range`、`min`、`max`、`sum`、`abs`、`sort`、`set` 等常用功能。

`deque`、`heapq` 等标准库在确有必要时允许使用，要解释关键操作。避免不必要的 lambda、复杂推导式、装饰器和过度封装。不是禁止一切函数：递归、回溯、独立判定逻辑及题目指定接口可以合理使用函数。

DP 优先保留容易理解的完整状态，不强行压缩为滚动变量。回溯使用 append → 递归 → pop，保存结果使用 `path[:]`。交换元素可以用 `tmp` 分步完成。

### 5. 输入和提交接口

默认可直接运行的顶层脚本，不额外包 `solve()` 或 `main()`。ACM 默认：

```python
import sys

# sys.stdin = open('input.txt', 'r')

data = sys.stdin.read().split()
```

随后严格按照题目格式解析。LeetCode 保留题目给定的 `class Solution` 和函数签名；明确要求返回值时使用函数；用户只要求处理给定数据时直接使用数据，不设计额外输入协议。

### 6. 注释与边界

注释简短、使用中文，重点说明核心逻辑、状态含义和易错处。减少无关代码、重复检查、无用 import 和不必要的 del。题目保证合法的条件不再大量防御性检查；题目明确要求处理的非法输入和边界必须正确处理。

## 四、结合仓库补充的约定

以下是对上述要求的具体化，不是要求每次回答都输出检查清单。

### 1. 看图时重点确认的条件

- 单组还是多组；第一项是 n、T 还是数据本身；是否读到 EOF。
- 求个数、具体方案、下标还是值；下标从 0 还是 1 开始；是否要求原地修改。
- 连续子数组还是子序列；恰好、至少、至多；严格大于还是大于等于。
- 数值是否允许负数、零和重复；图有向还是无向；是否保证连通、有序或无环。
- 同分规则、无解表示、输出顺序、小数位数和误差要求。

只有实际影响当前解法且无法从截图确定的内容才需要询问。样例不能代替数据范围；不因样例小就认定 O(n²) 足够。

### 2. 输入与接口补充

`read().split()` 适用于空白分隔的 token；如果空格、空行是字符串内容的一部分，应改为按行读取。输入很大时考虑一次性 split 的内存开销。

提交版本不激活 `sys.stdin = open(...)`，不带本地测试调用和调试 print。LeetCode 的链表、树节点使用平台接口，不依赖仓库里的 `binaryTree` 或 `ListNode` 辅助模块；独立脚本确需节点定义时再提供。

类型注解服从平台 Python 版本和题目签名。需要 `List`、`Optional` 时从 `typing` 导入，不从 `types` 导入。不要把调试用的 `(长度, 数组)` 当成只要求整数长度的题目返回值。

### 3. 正确性补充

- 二维列表的每一行单独建立，不使用 `[[0] * m] * n` 造成行共享。
- 不用 `sum`、`list`、`str`、`input` 等常用内置名字作无必要的普通变量，累加值可用 `total`、`current` 或 `tmp`。
- 二分明确区间含义、更新规则和终止条件，避免混用闭区间与半开区间模板。
- 滑动窗口说明适用条件；依赖正数的和窗口不能直接推广到含负数的输入。无重复字符窗口的 left 不能向后退。
- BFS 入队时标记，避免重复入队；`deque.popleft()` 从左侧取出最早入队项。
- DFS 全局访问集合与回溯当前路径分开理解，图上的全局访问记录不能照搬回溯随意撤销。递归可能很深时优先考虑显式栈，不能只提高递归上限就认为安全。
- DP 讲清状态、初始值、转移和遍历顺序。完整状态超过内存限制时需要压缩，并解释保留哪些依赖。
- 重复边应按题意处理，例如最短路中保留较小边权；Dijkstra 需要非负边权。
- 同分按题目规则决定是否更新。允许“不修改”或“无解”时正确初始化答案，避免答案下标未赋值。
- 浮点数按题目精度处理，不擅自添加改变题意的容差；能用整数运算时不无故引入浮点误差。

### 4. 复杂度与讲解补充

解释实际代码的复杂度，不能只背算法名称。切片、排序、列表查找、循环中的 sum、递归栈、结果拷贝和输出规模都可能影响复杂度。

字典和集合的查询通常按平均 O(1) 说明；列表 `pop(0)`、成员查找和 `index()` 通常为 O(n)。原地排序不表示整个算法必然 O(1) 额外空间。

区分辅助空间、保存结果的空间和包含输入后的总空间；ACM 的 `data` token 列表也是输入存储。按值域构建数组时用值域大小分析，不能只按元素数量 n 分析。

讲解尽量围绕“当前变量表示什么、这一步为什么不会漏解、何时得到答案”。需要时手推一小段关键状态，不默认输出长篇逐行解释或制作 HTML 动画。
